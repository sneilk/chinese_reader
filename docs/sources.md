# Источники контента: разбор целевых сайтов

Ответ на вопрос A3 из [concept-review.md](concept-review.md) §7 — названы `novelarrow.com` и `51shucheng.net`.
Дата первой проверки: 2026-08-05, метод — `curl` с браузерным User-Agent, без выполнения JS.
Дата повторной, живым браузером: 2026-09-04, снимки страниц — `scripts/snapshot_fixtures.py`.

## Что показала повторная проверка

Оба сайта дают ссылку «следующая глава», и оба до 2026-09-04 её не отдавали
сервису — по разным причинам, и обе видны только на живой странице.

**51shucheng: ссылка была, читать её никто не пробовал.** На каждой странице
главы стоит `<a id="BookNext" class="chapter-nav-btn next-btn">下一章 ›</a>` с
абсолютным адресом следующей главы. Адаптер её не читал вовсе, поэтому
`next_chapter_url` китайской главы был пуст **всегда**: обход книги на этом
сайте не делал ни шага, а читалка показывала «ссылки на следующую главу не
нашлось» под страницей, где эта ссылка нарисована.

**novelarrow: ссылку искали, но не там.** Живая кнопка вперёд — это голая
стрелка в `<svg>` без единого символа текста. `rel="next"` у неё нет, классы
сгенерированы Tailwind и слова `next` не содержат, а вся подпись лежит в
`aria-label="Next chapter"` — атрибуте, который общий поиск ссылки не смотрел.
Рукописная фикстура этого не показывала и показать не могла: в ней кнопка была
подписана словом, как её и представляли.

Отсюда правило, которое дороже обоих исправлений: **структурная фикстура
показывает то, что мы думаем о разметке сайта, а не то, что сайт отдаёт.**
Живые снимки теперь снимаются скриптом и лежат в `data/fixtures/` вне git;
тесты на них пропускаются, если снимков нет
(`backend/tests/test_adapter_next_chapter.py`).

## Итог в одну строку

**Ни один из двух сайтов не отдаётся обычному HTTP-клиенту:** 51shucheng закрыт Cloudflare-челленджем целиком, у novelarrow список глав подгружается клиентским JS. Значит, слой загрузки обязан работать через реальный браузер — это не оптимизация «когда-нибудь», а условие входа.

## 1. 51shucheng.net — китайский оригинал, основной сайт MVP

| Параметр | Значение |
|---|---|
| Роль | китайский режим, MVP (решение A5) |
| Движок | WordPress (в robots закрыты `/wp-admin/`, `/wp-includes/`) |
| robots.txt | `User-agent: *` → запрещены только служебные каталоги WP; объявлен `sitemap.xml` |
| Доступ без JS | ❌ HTTP 403, `cf-mitigated: challenge`, страница «Just a moment…» — **включая `/sitemap.xml`** |
| Доступ через headful-браузер | ✅ проверено с ВМ 2026-08-06: челлендж решается **сам**, ручных вмешательств ноль; профиль переживает перезапуск браузера и перезагрузку машины |
| Доступ через headless-браузер | ❌ 403 даже с живой `cf_clearance` в том же профиле — headful обязателен постоянно |
| Название | 无忧书城 — каталог художественной литературы, иероглифы упрощённые |
| Структура | `/{жанр}/{книга}/{номер}.html`; у книги-образца 550 глав; пагинации внутри главы нет; ссылок на `.txt` не найдено |
| Ссылка вперёд | ✅ `a#BookNext` в `nav.chapter-nav`, абсолютный адрес, подпись «下一章 ›». Рядом `a#BookPrev` (нет на первой главе) и `a#BookHome` на оглавление книги |
| Конец книги | у последней главы `#BookNext` ведёт на оглавление. Отличается тем, что адрес перестаёт быть адресом главы: `.html` в конце нет |
| Заголовок челленджа | «请稍候…» — китайская локаль, английские варианты вроде «Just a moment» здесь не приходят |
| Размер главы | 3157 иероглифов видимого текста, 76 абзацев, ~153 предложения. Около 40% текста в HTML — навигация, поэтому адаптер обязателен |
| Поведение на несуществующих адресах | Двойное. Мусорный путь и несуществующая книга → честный **404** с заголовком 页面没有找到. Несуществующий **номер главы внутри существующей книги** → **200 и страница оглавления книги** («мягкий 404»). Первое ловит загрузчик, второе может распознать только адаптер: статус и контент выглядят нормальными |

Практические следствия:

- `httpx`/`requests` + `trafilatura` не годятся даже как первая попытка — до HTML дело не доходит;
- нужен Playwright с **persistent context** (профиль браузера на диске): челлендж проходится один раз, куки живут дальше;
- первый заход — headful, возможно с ручным кликом; последующие — проверить, работает ли headless на тех же куках;
- каждая скачанная глава кэшируется в SQLite: повторное открытие не должно трогать сайт вообще;
- защита может измениться в любой момент — загрузчик обязан отличать «челлендж» от «404» и говорить об этом внятно, а не отдавать пустую главу.

## 2. novelarrow.com — английские переводы, второй режим

| Параметр | Значение |
|---|---|
| Роль | английский режим — **реализован**, см. [english.md](english.md) |
| Движок | Next.js (SSR + RSC), за Cloudflare |
| Язык контента | английский. На главной **ноль CJK-символов** — это агрегатор переводов, а не китайские оригиналы |
| robots.txt | `User-agent: *` → `Allow: /`, закрыты `/api/`, `/admin/`, `/login`, `/library`, `/history`, `/profile`, `/reports`. Отдельно `Disallow: /` для GPTBot, ClaudeBot, CCBot, Google-Extended, Bytespider, Amazonbot, meta-externalagent. Content-Signal: `search=yes, ai-train=no, use=reference` |
| Доступ без JS | ✅ 200 на главную, `/genre/<slug>`, `/novel/<slug>` — SSR-разметка приходит |
| Доступ через браузер | ✅ проверено 2026-09-04 с разработческой машины, **headless проходит**: челленджа на страницу главы нет вовсе |
| Список глав | ❌ в HTML страницы новеллы ссылок на главы **нет** — грузятся клиентом, судя по всему через `/api/`, который закрыт в robots. В живом браузере после исполнения JS они появляются, но опираться на это мы не стали: книга по-прежнему обходится цепочкой |
| Адрес главы | `/chapter/{книга}/{слаг-главы}` — **не** `/novel/…`, как предполагалось. Слаг содержит номер и название: `chapter-2-slave-caravan` |
| Ссылка вперёд | ✅ есть, но подписи у неё нет: `<a aria-label="Next chapter">` со стрелкой в `<svg>`. Ни `rel="next"`, ни слова `next` в классах — они сгенерированы Tailwind |
| Размер главы | 91 абзац, 1883 слова на снятой главе — в предполагавшийся диапазон 1500–4000 попадает |

Практические следствия:

- страницу-карточку новеллы можно разобрать из SSR-HTML, а вот оглавление и текст главы — только после исполнения JS, то есть снова реальный браузер;
- в `/api/` не ходить: он явно запрещён в robots, даже если технически доступен;
- сайт прямо запрещает обучение моделей на своём контенте. Отправка одного предложения в LLM ради разбора для себя — это не обучение, но: не собирать корпуса, не публиковать выгрузки, не поднимать публичный инстанс с чужим контентом.

**Отсутствие оглавления определило способ обхода книги.** Раз списка глав в разметке нет, а собирать адреса «по схеме» на Next.js бессмысленно (слаг главы из номера не выводится), единственный вход — ссылка «следующая глава». Отсюда `chapters.next_chapter_url` и обход цепочкой с жёстким потолком, [english.md](english.md) §6.

**Селектор текста главы в код не зашит.** Классы Next.js генерируются сборкой и меняются вместе с ней, поэтому адаптер ищет текст структурно — по самому насыщенному абзацами блоку ([english.md](english.md) §7). Точный XPath задаётся переменной `NOVELARROW_CONTENT_XPATH`, когда живая страница окажется на руках.

**Адаптер написан по описанию, а не по живой фикстуре.** Это осознанный долг: фикстура в `tests/fixtures/novelarrow_chapter.html` воспроизводит форму такой страницы, но не разметку конкретного адреса. Первый заход с ВМ — в §4.

Отдельно: раз novelarrow — это английский, а не китайский, два названных сайта ложатся ровно на два языковых режима. `51shucheng` → сегментация, `novelarrow` → лемматизация. Пересечения между ними нет, и делать их одновременно смысла тем более нет.

## 3. Что из этого следует для архитектуры

1. **Загрузчик за интерфейсом, две реализации:** `HttpFetcher` (быстрый, для будущих простых источников) и `BrowserFetcher` (Playwright, persistent profile). Выбор — по адаптеру сайта, а не по глобальной настройке.
2. **Адаптер на сайт** — не «на всякий случай», а обязательный: `adapters/51shucheng.py`, `adapters/novelarrow.py`, интерфейс «оглавление → главы» + «URL главы → заголовок и текст». Generic-фолбэк на `trafilatura` остаётся для случайных ссылок.
3. **Кэш обязателен и первичен.** Скачанная глава живёт в SQLite вместе с токенами. Это же даёт оффлайн-чтение бесплатно.
4. **Вежливость:** задержка между запросами, параллелизм 1, никаких обходов оглавления целиком «про запас» — качаем ту главу, которую читаем.
