# chinese_reader

Читалка веб-новелл для изучающего язык — китайских и английских. Глава
загружается по ссылке, режется на слова, переводится целиком и открывается на
телефоне: удержание на слове даёт подсказку с переводом, двойной тап — карточку
с переводом предложения и статьями из словарей, а поправленные вручную границы
слов запоминаются и применяются к следующим главам. Одним переключателем глава
показывается по-русски, и её же можно слушать вслух.

Проект личный, на одного пользователя. Отсюда и решения: SQLite вместо
сервера баз данных, отсутствие очередей, три экрана вместо кабинета.

## Как это работает

```
POST /api/chapters {url, follow}
   → браузер открывает страницу (headful под Xvfb — иначе сайт отдаёт 403)
   → адаптер сайта достаёт текст главы, отсекая навигацию, и объявляет язык
   → нормализация в канон: по нему считаются все офсеты
   → резка на предложения → токены (jieba или регулярка) → status=segmented
                                                            ↑ УЖЕ ЧИТАЕМА
   → перевод батчами ≤10 000 символов → status=ready
   → follow > 0: то же для следующих глав по ссылке вперёд
```

Пять статусов существуют ради одной границы: где глава перестаёт быть
читаемой. Отказ переводчика её не отменяет — текст и разметка уже в базе,
глава остаётся на `segmented` и читается без перевода.

Ключевая величина всюду — **офсет в каноне**. Токены, предложения, контексты
сохранённых слов ссылаются на один и тот же нормализованный текст, поэтому
разметку можно переделать, не трогая содержимое.

## Два языка, а не два приложения

Язык — свойство главы, а не режим приложения: главы обоих языков лежат в одной
базе и читаются вперемешку. Различаются ровно три вещи.

| | Китайский | Английский |
|---|---|---|
| Границы слов | их нет — нужен jieba со словарём | проставлены пробелами — хватает регулярки |
| Конец предложения | `。！？…` | точка, но не в `Mr.`, `e.g.`, `3.15`, `J. R. R.` |
| Направление перевода | `zh→ru` | `en→ru` |

Всё остальное — загрузка, офсеты, статусы, панель, личный словарь, экран
состояния — написано один раз. Подробности и обоснования: [english.md](docs/english.md).

Отдельно стоит **обход книги**: у английского источника оглавления в разметке
нет вовсе, поэтому главы догружаются цепочкой по ссылке «следующая глава» — с
жёстким потолком, остановкой на первом отказе и без повторных походов за тем,
что уже загружено. Загруженное складывается в книгу и открывается с экрана
«Книги»: у книги есть ключ (её адрес на сайте), у главы — место в цепочке.

## Из чего собрано

| Слой | Что там |
|---|---|
| `backend/app/fetchers` | загрузка через Playwright с постоянным профилем |
| `backend/app/adapters` | извлечение главы: адаптеры сайтов + generic-фолбэк |
| `backend/app/lang` | нормализация, предложения, токены обоих языков, пиньинь, леммы |
| `backend/app/providers` | Яндекс.Переводчик и SpeechKit за общими интерфейсами |
| `backend/app/services` | конвейер, обход книги, словари, личный словарь, бюджет, кэш озвучки |
| `backend/app/api` | ручки главы, озвучки, словаря, слов, диагностики |
| `web/src/reader` | рендер по токенам, жесты, панель перевода, вид перевода, озвучка |
| `web/src/screens` | ввод ссылки, чтение, книги и оглавление, словарь, состояние |

Зависимости выбраны скупо: на фронте только React и Vite, без библиотек
состояния и маршрутизации; на бэкенде FastAPI, SQLAlchemy, jieba, httpx.

## Запуск для разработки

```bash
# бэкенд
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/alembic upgrade head
PYTHONPATH=. .venv/bin/python scripts/import_cedict.py   # словарь и userdict
.venv/bin/uvicorn app.main:app --reload

# фронт (в другом окне)
cd web && npm install && npm run dev
```

Открывается на `localhost:5173`, запросы к `/api` проксируются на бэкенд.
Без ключа переводчика всё работает, только главы останавливаются на
`segmented` — это штатный режим, а не поломка. Без ключа SpeechKit глава
читается, но не звучит; кнопка «Слушать» честно скажет, чего не хватает.

Англо-русский словарь ставится отдельно и только для английских глав:

```bash
PYTHONPATH=. .venv/bin/python scripts/import_endict.py <файл.dsl>
```

Проверки: `.venv/bin/python -m pytest` и `.venv/bin/ruff check .` в `backend/`,
`npm test`, `npm run build` и `npm run lint` в `web/`.

Тесты фронта покрывают чистую логику и запускаются без DOM: браузерного
окружения нет намеренно. Жесты держатся на pointer-событиях и
`elementFromPoint`, которых в jsdom всё равно нет, — их проверяют руками в
браузере, а тесты сторожат то, что ломается **молча**: перевод офсетов из
кодовых точек в единицы UTF-16, границы предложений и разбор отказов API.

## Данные и лицензии

Словарные дампы в репозиторий не кладутся — качаются скриптами при настройке.

- **CC-CEDICT** — китайско-английский словарь, [mdbg.net](https://www.mdbg.net/chinese/dictionary?page=cc-cedict),
  лицензия [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
  Атрибуция обязательна и по условиям лицензии, и по-человечески.
- **БКРС** — большой китайско-русский словарь, [bkrs.info](https://bkrs.info/),
  ежедневная выгрузка в формате DSL.
- **Англо-русский словарь** — любой в формате DSL; путь к файлу передаётся
  скрипту импорта аргументом. Автоскачивания нет намеренно: постоянного
  объявленного адреса выгрузки, как у двух словарей выше, здесь не существует,
  и зашитая ссылка означала бы обещание, которое сломается тихо. Лицензию
  конкретного дампа проверяйте сами — она у разных словарей разная.

Тексты глав принадлежат их правообладателям: сервис загружает их для личного
чтения и никуда не публикует.
